# Shanks — RAG Chatbot for Amizone / College Portal

Shanks is a Retrieval-Augmented Generation (RAG) chatbot: it answers student
questions grounded in your college's real content (attendance policy, exam
rules, fees, etc.), and falls back to a live web search when a question is
outside that knowledge base — so it never just dead-ends on "I don't know."

## How it actually works

```
 student question
        |
        v
 embed question (sentence-transformers, local, free)
        |
        v
 search FAISS index of your college docs  --> best match confident?
        |                                            |
        | yes                                        | no
        v                                            v
 answer generated by LLM,                 live web search (DuckDuckGo)
 grounded ONLY in those chunks             --> answer generated by LLM,
        |                                     grounded ONLY in those results
        v                                            |
        -------------------- reply + source label ---
```

Two things keep this from being "vibe-coded":
1. **Separation of concerns** — ingestion (`ingest.py`), retrieval + generation
   (`rag_engine.py`), web fallback (`web_search.py`), and the API (`main.py`)
   are separate modules, not one giant script.
2. **Grounded answers only** — the LLM is instructed to answer only from the
   context it's given (knowledge base or web results) and to say plainly when
   it doesn't know, instead of inventing facts, dates, or "reviews."

Every reply also carries a **source badge** (Knowledge base / Web) in the UI,
so it's always clear where an answer came from — nothing is presented as more
certain than it is.

### Why this is efficient
- Embeddings are computed **once**, offline, in `ingest.py` — not on every chat request.
- The embedding model and FAISS index load **once at server startup**, not per-message.
- FAISS `IndexFlatIP` on normalized vectors gives cosine-similarity search that's
  near-instant for a knowledge base of this size (hundreds to low thousands of chunks).
- Web search is only called when actually needed (low KB confidence), not on every message.

## Project structure

```
shanks-chatbot/
├── backend/
│   ├── main.py            # FastAPI server + serves the frontend
│   ├── rag_engine.py       # retrieval + fallback + LLM generation
│   ├── ingest.py           # builds the vector index from your docs
│   ├── web_search.py       # free DuckDuckGo web fallback
│   ├── config.py           # all settings in one place
│   └── requirements.txt
├── data/knowledge_base/     # <-- put your REAL college content here
├── frontend/                # chat UI + Shanks avatar (plain HTML/CSS/JS)
├── vector_store/            # generated index (created by ingest.py)
├── .env.example
└── README.md
```

## Step-by-step setup in VS Code

### 1. Open the project
Unzip/copy the `shanks-chatbot` folder anywhere, then in VS Code:
`File > Open Folder... > shanks-chatbot`.

### 2. Create a virtual environment
Open a terminal in VS Code (`` Ctrl+` ``):
```bash
python -m venv venv
```
Activate it:
- Windows: `venv\Scripts\activate`
- Mac/Linux: `source venv/bin/activate`

VS Code may prompt "Select this environment for the workspace" — click yes.

### 3. Install dependencies
```bash
pip install -r backend/requirements.txt
```

### 4. Set up the LLM (free, local, default: Ollama)
```bash
cp .env.example .env      # Windows: copy .env.example .env
```
By default this project uses **Ollama** — a free model that runs entirely on
your own machine, no API key, no cost, no data leaving your Mac:
1. Install it from https://ollama.com/download
2. Pull the model once: `ollama pull llama3.1` (a few GB, one-time download)
3. Leave `.env` as-is — `LLM_PROVIDER=ollama` is already the default.

Prefer Claude or GPT instead? Open `.env`, comment out the Ollama lines, and
uncomment/fill in the Anthropic or OpenAI block instead.

### 5. Add your REAL college content
Open `data/knowledge_base/amizone_faq.md` and **replace the placeholder text**
with real information: your handbook, portal help pages, attendance/exam/fee
policies, contacts. Add more `.md`/`.txt` files in that folder if you like —
one per topic works well.

**This step matters most** — the chatbot is only as good and as honest as
the content you give it. Don't skip it or leave the sample text in for your demo.

### 6. Build the vector index
```bash
python backend/ingest.py
```
First run downloads the (free, local) embedding model — this needs internet
once, then works offline. Re-run this script any time you edit the knowledge
base files.

### 7. Run the server
```bash
uvicorn backend.main:app --reload --app-dir backend
```
You should see `Shanks is ready.` in the terminal.

### 8. Open the app
Go to **http://127.0.0.1:8000** in your browser. That's it — frontend and
backend are served from the same place.

## Presenting it

- Ask something that's clearly answered by your knowledge base (e.g. "what's
  the minimum attendance percentage?") — you'll see the **Knowledge base**
  badge, answer grounded in your actual college docs.
- Ask something general/current (e.g. "what's a good way to prepare for
  campus placements this year?") — you'll see the **Web** badge, showing the
  live-search fallback kicking in.
- That contrast is the whole point to demonstrate live: **it knows what it
  knows from your college, and honestly reaches further when it doesn't.**

## Extending it later (optional, not required for the demo)
- Swap the LLM provider by changing `LLM_PROVIDER` in `.env`.
- Tune `TOP_K` / `SIMILARITY_THRESHOLD` in `config.py` if answers feel too
  eager to fall back to web, or not confident enough to use the KB.
- Add chat history/multi-turn memory (currently each question is independent —
  a natural "future work" line for your report if you want one).
